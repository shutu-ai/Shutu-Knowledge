# Shutu-Knowledge 0.3 gap analysis

## Baseline evidence

The 0.2 parser contract returns `Title`, `Text`, and `NeedsOCR`. The PDF
parser can coordinate-reassemble text and the Office parser can extract
paragraph, slide, and cell text, but those parsers expose no page, slide,
sheet, cell, block, table, or figure provenance to ingestion.

The Knowledge model currently stores documents and chunks. A chunk retains
heading and context text, while SQLite has no durable document-node or
chunk-to-node representation. Search already preserves document, chunk,
source-version, and index-generation identity, so the 0.3 foundation extends
that path instead of replacing hybrid retrieval or generation visibility.

## Scope for the first 0.3 slice

1. Add a versioned, parser-independent Document IR package with deterministic
   node IDs and source anchors.
2. Add backward-compatible SQLite tables for IR nodes, relationships, and
   chunk-node links. Existing document/chunk rows remain authoritative for
   legacy callers.
3. Carry the IR from built-in parsers into ingestion and persist it only after
   the document generation is staged. A failed parse cannot publish nodes.
4. Add structural metadata to chunks and search hits incrementally; preserve
   the existing JSON fields and retrieval algorithms.

## Deliberate deferrals

Full visual understanding, GraphRAG, ontology/entity extraction, a new
vector database, and a second transaction or worker system are outside this
slice. OCR and external parser fallbacks continue to produce text; when they
cannot provide a precise anchor, the IR uses an explicit degraded logical
anchor rather than inventing a page or bounding box.

## Acceptance evidence

The implemented foundation now proves deterministic IR IDs, migration from a
pre-0.3 database, parser-specific anchors for PDF, PPTX, and XLSX fixtures,
chunk-node links, generation-scoped delete cleanup, structure-filtered search,
source-accurate citations, and preservation of the existing text/search API.
The checked-in golden corpus manifest covers PDF, DOCX, PPTX, XLSX, English,
Chinese, and mixed-language cases; its office/PDF containers are generated
deterministically in memory from reviewable source fixtures.

All successful parser and fallback paths publish the same IR contract. A
fallback may use a logical anchor, but it is never allowed to return only an
unstructured text side channel. Local metrics expose parser selection,
fallback count, parse duration, node/table/figure counts, and chunk count
without recording document content.
