# 0.4 Semantic API & Knowledge Explorer — Integration Slice

Status: semantic compilation, retrieval, context, provenance, and Living Wiki
are exposed through the local REST API and a minimal Web Knowledge Explorer.
The existing `/api/search` contract is unchanged.

## REST API

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/bases/{id}/semantic/compile` | Run deterministic incremental compilation and atomically publish it. |
| `GET` | `/api/bases/{id}/semantic` | Return the active immutable compilation and unit/relation graph. |
| `POST` | `/api/bases/{id}/semantic/search` | Activate Concepts/Topics/Summaries (or requested Facts) with routing diagnostics. |
| `POST` | `/api/bases/{id}/semantic/context` | Compile a bounded semantic+evidence ContextPackage. |
| `GET` | `/api/bases/{id}/semantic/wiki` | Return the regenerable Wiki view and per-page Markdown/evidence. |
| `GET` | `/api/semantic/units/{unitId}/evidence` | Follow `derived_from` to exact IR/chunk provenance. |

All responses use the existing `{ ok, value }` envelope and standard error
mapping. A KB without an active compilation returns `404 not-found`; legacy
search remains available.

### Request examples

```json
POST /api/bases/base-1/semantic/search
{ "query": "总结整个知识库", "topK": 8 }
```

```json
POST /api/bases/base-1/semantic/context
{ "query": "How does worker beta affect capacity planning?", "tokenBudget": 2048 }
```

Compilation is deterministic and offline, but may inspect every ready Document
IR on a first run. The frontend API client uses a ten-minute timeout for that
endpoint.

## Web Knowledge Explorer

The Web navigation now includes **Knowledge**. For the selected base it shows:

* compilation action;
* active generation and compiler/model/prompt provenance;
* Fact/Concept/Topic/Summary/Relation counts;
* a bounded Knowledge Unit explorer with confidence, direct evidence count,
  and derived-from count;
* semantic activation results with routing terms and evidence closure size;
* the rendered ContextPackage, token budget, intent, evidence/citation counts;
* a regenerable Living Wiki view with generated-content boundary and exact
  source evidence.

The Explorer is read-only. Compilation is explicit and never required to use
0.3 Recall Test or existing search.

## Agent integration

The existing public Extension tool inventory adds read-only
`knowledge_compile_context`. It consumes an already active semantic compilation
and returns compiled context, exact evidence, and citations. It does not mutate
Knowledge state or require a Shutu-Agent core change. See
[shutu_agent_0_4_requirements.md](shutu_agent_0_4_requirements.md).

## Frontend API client

`web/src/api.js` now exposes:

* `semanticCompilation`
* `compileSemanticMemory`
* `searchSemanticMemory`
* `compileKnowledgeContext`
* `semanticWiki`
* `semanticUnitEvidence`

The contract test verifies Agent-extension proxy path handling.
