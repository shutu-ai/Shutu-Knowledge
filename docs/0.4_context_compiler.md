# 0.4 Context Compiler — PH5

Status: query-specific Semantic Memory + Evidence context assembly implemented.
The output is a bounded `ContextPackage`, not an unbounded dump of Wiki pages or
top-K chunks.

## Pipeline

```text
query
  ↓
active semantic compilation
  ├─ Concept / Topic / Summary activation
  ├─ Fact activation
  ↓
semantic Concept/Topic activation
  ↓ title-based query expansion
existing 0.3 hybrid evidence search
  ↓
deduplication + section budgets + evidence selection
  ↓
ContextPackage + rendered context + citations + diagnostics
```

`Service.CompileKnowledgeContext(baseID, query, tokenBudget)` uses the active
immutable semantic generation and the existing 0.3 hybrid search in the same
base. Activated Concept/Topic titles become bounded additional query variants,
improving cross-document recall while the 0.3 pipeline remains the
exact-evidence authority.

## ContextPackage

The structured package contains:

* query and compiler version;
* semantic generation;
* knowledge orientation (`Topic`/`Summary`);
* relevant concepts;
* relation slot (empty until benchmark-gated relation expansion);
* critical facts;
* exact evidence items;
* citations;
* token budget and estimate;
* rendered context;
* selection diagnostics.

The internal compiler version is `semantic-evidence-v1`.

## Token control

The default budget is 4096 tokens. PH5 clamps explicit requests to
`512..32768` and applies bounded allowances:

* knowledge orientation: at most one quarter;
* concepts: at most one tenth;
* relation slot: at most one twentieth;
* facts: at most one eighth;
* exact evidence receives the remaining budget.

Evidence is ranked by the existing search score, deduplicated by document and
chunk/text identity, then selected in order. Oversized evidence is cropped only
when enough budget remains to preserve a useful excerpt. The final rendered
context is token-checked; tests reject packages above budget.

More knowledge does not automatically mean more context: summary/concept
orientation can replace repeated evidence while exact citations remain present.

## Dynamic context and provenance

Each query receives a different package. The compiler does not preload a Wiki
or a fixed KB preamble. Semantic summaries retain their unit provenance in the
compilation, while exact evidence/citations come from the existing SearchHit
context window and Citation v2 projection.

## Diagnostics

`ContextDiagnostics` reports:

* semantic hit count;
* fact hit count;
* evidence candidate count;
* selected evidence count;
* duplicate evidence count;
* dropped evidence count.

This is sufficient to audit why context changed without exposing unrelated
knowledge-base content.

## Query routing

Context compilation uses deterministic `lexical-rules-v1` AUTO routing. The
full `QueryPlan` is embedded in `ContextPackage.Routing`; intent changes the
semantic/fact candidate balance while retaining exact evidence. See
[0.4_query_routing.md](0.4_query_routing.md).

## Remaining limits

* Relation expansion is intentionally empty until PH8 benchmark evidence.
* Context assembly is a service method, not yet exposed through HTTP/Agent API.
* Answer-quality improvement cannot be claimed before PH9 benchmark execution.
