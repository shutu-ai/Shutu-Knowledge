# 0.4 Incremental Compilation & Delete Propagation — PH3

Status: durable incremental compilation implemented for compiler v0. Updates and
deletes are queued, unchanged units carry forward into a new immutable
generation, and dirty provenance is removed/recomputed without rebuilding the
0.3 Evidence Index.

## Dirty inputs

Migration `0020_semantic_compilation_queue.sql` adds a durable per-document
queue:

```text
base_id + doc_id
change_type = updated | deleted
index_generation
source_version
content_hash
created_at / updated_at
resolved_generation
```

A successful document generation activation marks that document `updated`. A
document delete fence marks every affected physical document `deleted` before
evidence cleanup. Repeated changes collapse to the latest row. Pending rows are
ordered deterministically and survive process restarts.

The compiler additionally stores a `source_fingerprints` map in each
compilation:

```text
document ID -> active IR generation + source version + title hash + IR text hash
```

Therefore both queued changes and fingerprint drift are detected. If activation
succeeds but queue marking is interrupted, a later compile still discovers the
mismatch.

## Incremental path

`Service.CompileSemanticMemory(baseID)` now:

1. loads active ready documents with Document IR and chunk-node links;
2. loads the active semantic generation and pending queue;
3. computes added/changed/deleted document IDs;
4. returns the active generation unchanged when there is no drift;
5. compiles only added/changed documents;
6. sanitizes the previous generation by removing dirty/deleted sources;
7. drops summaries and upward units that lose all support;
8. remaps retained deterministic unit IDs into the new generation;
9. merges canonical Facts/Concepts/Topics with the dirty compilation;
10. validates the complete graph;
11. writes and atomically activates the new immutable generation;
12. resolves the queue.

An unchanged document is not reparsed, rechunked, re-embedded, or recompiled.
The existing Evidence Index is never rebuilt.

## Cross-document propagation

The merge is provenance-aware rather than a blind union:

* a Fact supported by both changed and unchanged documents keeps the unchanged
  source and receives the recomputed source;
* a Fact supported only by a deleted document is removed;
* Concepts retain unaffected Fact dependencies and merge new dependencies;
* Topics retain unaffected Concept dependencies;
* deleted document Summaries are removed and replaced only if the document
  still exists;
* every output unit must still resolve to exact IR/chunk evidence.

This permits a repeated fact to remain one canonical unit while its evidence
membership expands or contracts.

## Delete policy

Deleting a document does not delete shared knowledge merely because one source
disappeared. The compiler removes that document's evidence and then chooses the
appropriate effect:

* remove a unit with no remaining provenance;
* recompute a Summary for an updated document;
* keep a shared Fact/Concept/Topic while downgrading its evidence membership;
* preserve the active generation until the replacement generation validates and
  activates.

Tests walk every surviving Summary through `ResolveEvidence` and reject any
pointer to a deleted document.

## Generation isolation and restart

* Building generations are complete transactional writes.
* Activation retires the previous generation and publishes the new one in one
  transaction.
* A partial unique index allows one active generation per base.
* Readers query generation-scoped unit/relation rows, so they see the old or new
  complete set, never a mixed/partial compilation.
* Pending queue rows survive restart.
* If activation completes but queue resolution is interrupted, the next no-op
  compile observes matching fingerprints, resolves the queue, and does not
  create another generation.
* If compilation fails before activation, the previous generation remains
  active and the pending queue remains durable.

A concurrent-reader test activates a new generation while repeatedly loading
the active compilation and rejects unexpected generations, mixed unit
generations, or partial unit/relation counts.

When an active semantic generation exists, document deletion invokes the
incremental propagation path after evidence cleanup. If deterministic
replacement unexpectedly fails, the old generation is retired rather than
exposing provenance to deleted evidence, while the durable queue remains for a
later rebuild. Base deletion removes semantic compilations, units, provenance,
relations, and queue rows only after base-scoped evidence cleanup completes.

## Remaining limits

* Compilation is synchronous through the service method; a background scheduler
  and HTTP/Agent operation API are later phases.
* Update currently recompiles the semantic projection for the dirty document
  and its upward dependencies, but does not yet use a fine-grained node diff.
* Conservative versioned supersession is reconciled after each merge; general
  contradiction detection is not inferred yet.
* LLM-assisted enrichment remains deferred.
