# 0.4 Knowledge Compiler v0 — PH2

Status: deterministic compiler v0 implemented for the PH2 unit set:
Fact, Concept, Topic, and Summary. It is wired to the Knowledge service as an
explicit optional operation with durable incremental update/delete propagation.
LLM-assisted enrichment is deliberately deferred. See
[0.4_incremental_compilation.md](0.4_incremental_compilation.md) and [0.4_lightweight_relations.md](0.4_lightweight_relations.md).

## Pipeline

```text
active ready documents
        ↓
active Document IR generation + existing chunk_node_links
        ↓
explicit fact extraction
        ↓
concept normalization / deduplication
        ↓
topic grouping
        ↓
document summaries
        ↓
validated KnowledgeUnit graph
        ↓
atomic semantic compilation generation
```

The builtin compiler is fully deterministic and offline:

```text
compiler: shutu-builtin
compiler_version: 0.4.0-ph2
model: deterministic
model_version: v1
prompt_version: none
```

It does not call an LLM and does not depend on a model provider. The service
can therefore compile semantic memory in the same offline-first posture as the
0.3 runtime.

## Fact extraction

The compiler scans paragraph, list-item, table, table-row, table-cell, and
caption text. It emits bounded candidates only when a sentence contains an
explicit predicate or definition form (English predicates, common Chinese
predicates, or a single colon definition).

Guardrails:

* documents are capped at 128 fact candidates;
* code, headers, footers, footnotes, and document roots are ignored;
* each candidate retains its exact IR node and first existing chunk link;
* identical normalized facts are merged across documents while preserving every
  source generation/version;
* no sentence is forced into a fact.

This is intentionally conservative. PH2 optimizes for provenance and
correctness before recall.

## Concepts and topics

Concept candidates come from document titles, headings, and sections. They are
normalized to lowercase canonical keys, aliases are retained, and identical
keys merge across documents. A concept derives from facts found under matching
headings or containing the concept label. If a heading has no extracted fact,
the concept points directly to the heading/root IR provenance rather than
inventing support.

Topics come from top-level headings and document titles. Concepts are assigned
by deterministic token/substring overlap. Topic units derive from their member
concept units; each base is capped at 64 PH2 topics.

No fixed ontology and no external graph service are introduced.

## Summaries

Every compiled document receives one deterministic Summary unit keyed by
document ID and source version. Its content is a bounded outline-oriented
summary with key concepts, and its provenance is the explicit set of concept
and fact units from that document. Documents without useful facts fall back to
root IR provenance rather than producing an unsupported summary.

## Service integration

`Service.CompileSemanticMemory(baseID)`:

1. verifies the base is active;
2. reads ready documents;
3. skips legacy rows with no Document IR rather than fabricating nodes;
4. loads the active IR generation;
5. loads existing `chunk_node_links` without rebuilding evidence;
6. runs the deterministic compiler;
7. writes a complete building generation transactionally;
8. atomically retires the previous semantic generation and activates the new
   one.

`Service.GetSemanticCompilation(baseID)` returns the active generation or
`ErrNotFound` for a 0.3 KB that has never compiled semantic memory. Existing
hybrid search continues to work before and after compilation.

`Service.ResolveSemanticUnitEvidence(unitID)` follows derived-from links to the
exact Document IR node/chunk provenance.

## Current limits

These are real PH2 limits, not hidden claims:

* Fact/concept/topic extraction is heuristic and deterministic, not LLM-enriched.
* Concept clustering is lexical and conservative.
* One benchmark-justified same-node Fact→Fact `related_to(sequence)` edge is emitted by compiler v0.
* Conservative versioned temporal supersession is inferred; same-version contradiction detection is not.
* There is no background scheduler yet; explicit compilation consumes the durable restart queue.
* Semantic units are not yet consumed by final context assembly.
* No benchmark claim is made until PH9 runs the 0.3-vs-0.4 suite.

These limits define the later-phase work rather than weakening the 0.4 release gate.
