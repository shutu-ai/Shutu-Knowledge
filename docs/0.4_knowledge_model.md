# 0.4 Knowledge Model — PH1 Foundation

Status: PH1 model and additive storage foundation implemented. Compilation,
semantic retrieval, context assembly, Wiki views, and benchmarks remain later
0.4 phases.

## Design rule

The 0.3 Evidence Layer remains authoritative. A Knowledge Unit never replaces a
Document IR node, chunk, raw source, or citation. Compiled knowledge is a
separate, optional Semantic Memory projection that must resolve back to exact
evidence.

```text
KnowledgePage / Topic / Summary / Concept
        ↓ explicit derived_from
        Fact
        ↓ exact provenance
Document IR node + existing chunk
        ↓
document generation / source version / raw source
```

## Unit model

`internal/semantic.Unit` supports the deliberately small PH1 set:

* `fact`
* `concept`
* `topic`
* `summary`
* `knowledge_page`

Every unit has:

* deterministic ID scoped by base, immutable compilation generation, type, and
  canonical key;
* title, canonical key, content, aliases, and parent-unit hierarchy;
* confidence and lifecycle status (`active`, `superseded`, `conflicted`,
  `deleted`);
* `valid_from`, `valid_to`, and `superseded_by`;
* direct evidence sources and/or explicit `derived_from` unit links;
* compiler/model/prompt identity through its compilation generation;
* metadata without promoting incidental fields to core schema.

A unit with neither a source nor a derived-from target is invalid. Cycles,
duplicate canonical identities, invalid confidence, inverted time intervals,
unsupported statuses, and missing parent/successor references are rejected before
write.

## Relations

`internal/semantic.Relation` initially permits only:

* `derived_from`
* `part_of`
* `mentions`
* `related_to`
* `supports`
* `contradicts`
* `supersedes`
* `same_topic`

Relations are typed unit-to-unit records with confidence, temporal fields, and
provenance. Except for the projection-only `derived_from` relation, a semantic
relation must carry exact evidence. There is no generic property-graph schema or
text-to-Cypher layer.

## Evidence provenance

An evidence source is a typed pointer to:

* document ID;
* immutable document index generation;
* source version;
* Document IR node ID and/or existing chunk ID;
* source anchor metadata;
* deterministic source order.

`semantic.ResolveEvidence` follows every `derived_from` edge and returns all
reachable exact evidence pointers. It detects missing targets and cycles, so a
generated Knowledge Page cannot claim support that cannot be audited.

## Compilation generations

`internal/semantic.Compilation` groups units and relations from one compiler run
and records:

* base and immutable generation;
* state (`building`, `active`, `retired`, `failed`);
* compiler and compiler version;
* model and model version;
* prompt version;
* source document IDs;
* metadata and completion time.

`semantic.Store.CreateCompilation` validates the full graph and writes a
building generation in one transaction. Nothing is active until
`ActivateCompilation` retires the previous active generation and publishes the
new one in a second transaction. A partial unique index enforces at most one
active generation per base. This is the storage foundation for restart recovery
and generation isolation.

## SQLite storage

Migration `0019_semantic_knowledge.sql` adds:

* `knowledge_compilations`
* `knowledge_units`
* `knowledge_unit_sources`
* `knowledge_unit_derived_from`
* `knowledge_relations`
* `knowledge_relation_sources`

Indexes cover active-unit lookup, canonical identity, parent traversal,
supersession, subject/object relation traversal, and exact evidence lookup. All
tables are additive; no 0.3 table is rewritten.

## Compatibility contract

* A migrated 0.3 database remains valid with zero semantic rows.
* Existing search does not query the semantic tables.
* Existing Document IR and Evidence Indexes are not rebuilt.
* No external graph/vector/database service is introduced.
* No LLM is required by the model itself; future compiler enrichment remains
  optional and versioned.
* The storage-format compatibility envelope is unchanged because migration 0019
  only adds optional tables.

## Verified in PH1

* Deterministic unit/relation identity.
* Local and graph-wide model validation.
* Explicit multi-level provenance resolution.
* Transactional creation of a complete building generation.
* Atomic active-generation replacement.
* Null-safe round trips for optional hierarchy and temporal fields.
* Additive migration with legacy tables present.

## Not yet implemented

The following are intentionally deferred to later phases rather than silently
claimed by the model:

* Fact/Concept/Topic extraction and normalization.
* Incremental compiler orchestration and dirty-set propagation.
* Delete/recompute policy integration with the existing document lifecycle.
* Semantic search and embeddings.
* Context compilation and query routing.
* Wiki rendering.
* 0.3-vs-0.4 benchmark and release gate.
