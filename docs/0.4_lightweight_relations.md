# 0.4 Lightweight Relations — PH8

Status: enabled only after the SmartCare/telecom benchmark exposed a missing
second hop that lexical fact activation could not recover.

## Enabled relation

Compiler v0 emits one conservative relation:

```text
related_to(sequence)
Fact A -> Fact B
```

A relation is emitted only when:

* A and B are adjacent explicit facts;
* both come from the same Document IR node;
* both retain exact provenance;
* both pass the deterministic explicit-fact guards.

This captures local discourse such as:

```text
Handover KQI aggregation uses the N2 interface.
The N2 interface depends on AMF relocation.
```

It does not perform general OpenIE, entity typing, text-to-Cypher, or graph
database reasoning.

## Context traversal

For a routed `multi_hop` query, Context Compiler:

1. activates Concepts/Topics/Facts;
2. follows active `related_to(sequence)` edges for at most two hops;
3. adds newly reached active Facts;
4. adds bounded relation statements to `ContextPackage.Relations`;
5. keeps exact evidence and citations authoritative.

The bounded traversal is deterministic and cannot expand the entire graph.

## Benchmark justification

Before sequence relations, the SmartCare query activated:

* registry → handover KQI;
* handover KQI → N2;

but missed:

* N2 → AMF relocation.

The relation ablation now recovers the full four-step professional causal chain:

```text
CCA offset registry
  → handover KQI aggregation
  → N2 interface
  → AMF relocation
  → handover delay / KQI impact
```

This is the measured condition required before enabling a relation mechanism.
