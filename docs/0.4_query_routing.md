# 0.4 Query Routing — PH6

Status: lightweight deterministic AUTO routing implemented for context
compilation. It classifies the 0.4 query families and selects evidence,
semantic, hierarchy, relation, or hybrid lanes without an agent planner.

## Supported intents

| Intent | Example signals | Primary lane | Secondary lane |
|---|---|---|---|
| `fact` | “What is…”, “多少”, default question | evidence | semantic facts |
| `local_document` | “this document”, “本文” | evidence | semantic summary |
| `global` | “summarize”, “whole knowledge base”, “整体” | hierarchy | evidence |
| `cross_document` | “across documents”, “所有文档” | hybrid | evidence |
| `comparison` | “compare”, “difference”, “对比” | hybrid | evidence |
| `multi_hop` | “how does X affect Y”, “导致”, “依赖” | relation | evidence |
| `temporal` | “current”, “version”, “最新”, “历史” | evidence | semantic facts |

The router is `lexical-rules-v1`. Signals, selected intent, confidence, lanes,
and router version are returned in `QueryPlan`. `QueryPlan.Describe()` provides
compact diagnostics.

## Routing invariants

* Exact fact questions stay evidence-first; they are not forced through a graph.
* Every route keeps exact evidence available.
* Global/comparison questions prefer Topic/Summary orientation before evidence.
* Multi-hop requests concept/relation orientation, but relation traversal is
  empty until PH8 is benchmark-gated.
* Temporal queries remain evidence-first until temporal fact lifecycle logic is
  populated by later compilation stages.
* Routing never mutates the query and never requires an LLM.

## User-facing mode mapping

The existing 0.3 search API remains unchanged:

* legacy `lexical`, `vector`, `hybrid`, and `auto` search modes continue to mean
  evidence retrieval lanes;
* `Service.SearchSemanticMemory` is the explicit KNOWLEDGE lane;
* `Service.CompileKnowledgeContext` is the HYBRID path and applies AUTO routing;
* `Service.PlanKnowledgeQuery` exposes diagnostics without retrieval.

No user is required to understand these internal modes. The default 0.4 path is
AUTO.

## Context integration

`ContextPackage.Routing` carries the full deterministic plan. Context counts
now vary by intent, for example:

* global: more Topic/Summary candidates, fewer facts;
* multi-hop: more concepts/facts for relation expansion;
* exact fact: fewer broad summaries and more exact fact/evidence candidates.

Remaining work: HTTP/Agent API exposure, benchmark validation of routing
accuracy, and actual relation traversal after PH8 ablation.
