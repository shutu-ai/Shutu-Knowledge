# 0.4 Reference Research — Knowledge Compiler & Semantic Memory

Status: PH0 complete. Research date: 2026-09-18.

This research is mechanism-oriented, not architecture-copying. Each reference was
checked against its current public repository documentation or source on the
default branch listed below. The goal is to identify mechanisms that can make
Shutu-Knowledge behave as if the LLM has internalized a knowledge base while
retaining exact evidence, provenance, update, deletion, and version control.

## Cross-cutting findings

1. **Compilation is the shared direction, not a specific artifact.** WeKnora and
   RAGFlow both moved from returning chunks to maintaining reusable derived
   knowledge. Shutu should implement a durable core model, not chase their
   complete product surfaces.

2. **Associative activation beats larger top-K.** HippoRAG and LightRAG support
   linking concepts/facts/relations before retrieval. Shutu can approximate this
   locally by canonicalizing concepts, linking facts to evidence, and expanding a
   bounded relation neighborhood.

3. **Global questions require precompiled abstraction.** GraphRAG community
   reports and RAPTOR summaries address the same failure: many relevant chunks
   cannot be safely aggregated by the caller. Shutu needs topic and hierarchy
   summaries with descendant provenance.

4. **Professional corpora need alignment, not only more graph edges.** KAG's
   knowledge/chunk mutual indexing and semantic alignment are directly relevant
   to SmartCare, 3GPP, and product manuals. A lightweight canonical vocabulary
   is more valuable than a full ontology engine.

5. **Lifecycle is part of the model.** Graphiti, LightRAG, and WeKnora all need
   deletion, update, rollback, or temporal semantics. Shutu must define unit
   validity and delete propagation before building richer retrieval.

6. **Cost control is a design boundary.** Every adopted mechanism needs a
   deterministic/offline path, bounded work, cancellation, restart recovery, and
   an ablation result. Relations, graph traversal, recursive summaries, and Wiki
   generation cannot become unconditional release blockers.

## Adopt / defer / reject

### Adopt in 0.4

* Core `KnowledgeUnit` model with Fact, Concept, Topic, Summary, hierarchy, and
  typed Relation records.
* Every derived unit resolves to Document IR nodes and existing chunks; exact
  citation remains authoritative.
* Per-document and cross-document compilation generations with atomic
  publication, invalidation, delete propagation, and restart recovery.
* Semantic memory retrieval over concepts/topics/summaries.
* Dynamic context compilation that fuses semantic memory and evidence under one
  token budget.
* Query routing for fact, global, cross-document, multi-hop, and temporal
  intents, with diagnostics and graceful fallback.
* Wiki as a regenerable projection of KnowledgeUnits, not a primary store.
* Lightweight SQLite relation/adjacency records only when benchmark-ablated.

### Defer to 0.5+

* Domain ontology engineering and logical-form reasoning.
* Recursive full-corpus clustering after every update.
* Rich Wiki editor beyond read/regenerate/status visibility.
* Audio/video and broad VLM multimodal compilation.
* User feedback learning and autonomous maintenance.
* Distributed graph engines or property-graph store integrations.

### Reject for 0.4

* Neo4j, PostgreSQL, Elasticsearch, Redis, Kafka, graph servers, microservices,
  or cloud-only dependencies.
* Copying WeKnora/RAGFlow product architecture or UI scope.
* Replacing the existing 0.3 evidence index.
* Mandatory full-KB recompilation for migration.
* Unproven relations or graph traversal kept merely for feature completeness.
* Generated knowledge without exact provenance.

## Benchmark implications

The reference research changes the benchmark from “does graph/wiki exist?” to
measurable internalization:

* **Fact:** preserve or improve 0.3 exact recall and citation precision.
* **Global:** compare answer quality and context tokens using 0.3 top-K versus
  0.4 topic/hierarchy summaries.
* **Cross-document:** measure canonical-concept recall across documents and
  contradiction explanation quality.
* **Multi-hop:** measure two-hop relation path recall and answer correctness,
  including ablation with relation expansion disabled.
* **Temporal:** measure current-version selection, superseded-fact rejection,
  and historical explanation accuracy.
* **Reuse/efficiency:** count compilation reuse, repeated extraction avoided,
  average context tokens, and answer quality at equal token budgets.

PH0 stop-rule answer: **yes** — the researched mechanisms materially improve
knowledge internalization if and only if they are implemented as a provenanced,
incremental core model and validated by the above 0.3-vs-0.4 benchmarks.
