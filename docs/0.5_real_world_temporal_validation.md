## Targeted fixes validated

The validation exposed P1 selection failures. The fixes were narrowly scoped and
each kept an existing version boundary:

1. Explicit and historical requests now fail closed instead of falling back to
   another version when requested evidence is absent.
2. Unknown-order versions no longer win a “latest” resolution.
3. Current resolution handles combined release-filename identities without
   treating the release filename as an unknown suffix.
4. Exact provenance from version-matched Knowledge Units is projected into
   context candidates when lexical retrieval splits version tokens.
5. Compact 3GPP filenames such as `v181200p` normalize to `18.12.0`.

Regression coverage is in
`internal/semantic/context_temporal_test.go` and
`internal/semantic/temporal_test.go`.

## Remaining gaps

1. **Primary — ambiguous temporal range/history reasoning:** 0/8 strict
   successes. The router does not yet build a bounded multi-version range from
   an ambiguous phrase such as “earlier release stages.”
2. **Secondary — current resolution:** 4/12 strict failures on generic product
   pages, draft-family filenames, or mixed report titles. This must be observed
   further after the primary fix.
3. **Deferred — parser-native dates/domain extraction:** useful for broader
   CJK/PDF coverage, but not the immediate measured blocker.

A 0.6 start should therefore be limited to the primary gap, with a written
entry/exit gate. No architecture rewrite is justified by this run.
