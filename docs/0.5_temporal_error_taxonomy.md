# Shutu-Knowledge 0.5 Temporal Error Taxonomy

| ID | Failure | 0.5 behavior |
|---|---|---|
| T1 | Version metadata missing | Optional metadata stays null/UNKNOWN; title fallback is deterministic and provenance-backed. |
| T2 | Version metadata extracted wrong | Identity parser accepts only semantic-ish versions, release numbers, 3GPP document forms, and explicit tokens. |
| T3 | Knowledge merged across versions | Fact dedup key includes normalized version scope; distinct versions remain distinct until a comparable supersession relation exists. |
| T4 | Superseded fact still active | Same-scope, newer-version facts supersede old facts; history remains searchable for historical/evolution requests. |
| T5 | Query temporal intent missed | Current, historical, explicit-version, evolution, compare, validity, introduced, and removed signals are parsed separately. |
| T6 | Context wrong-version selection | Current/current-validity requests use compiled latest comparable scope; explicit scope has precedence. |
| T7 | Conflict not exposed | Same-scope same-version contradiction becomes `conflicted`, not deleted; conflict evidence remains queryable. |
| T8 | Latest-version resolution wrong | Latest resolution requires a comparable order. If impossible, diagnostics say UNKNOWN rather than guessing. |
| T9 | Historical query resolved to current | Explicit/historical requests filter and boost the requested identity; superseded units remain available. |
| T10 | Final LLM temporal reasoning error | Context carries intent, resolved version, status, and exact evidence. If evidence is correct but reasoning is wrong, the failure is LLM-side, not reclassified as compilation. |

False supersession is treated as P1/P0 evidence: different values are not
automatically grouped unless subject/predicate scope matches and the source
identities have a proven order.
