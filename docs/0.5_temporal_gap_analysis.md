# Shutu-Knowledge 0.5 Temporal Gap Analysis

## Scope

This audit uses the committed 0.4 real-world validation artifact
(`benchmarks/real_world_internalization/results/baseline_0.4.json`) and the
Temporal / Version queries already represented there. It is deliberately not a
new architecture audit.

## Baseline evidence

The strongest 0.4 failure is the current-release probe:

| Corpus | Query | Baseline criteria | Baseline score |
|---|---|---:|---:|
| A | “What is the current Open5GS release?” | 0 / 1 | 0.333 |

The evidence set is mixed with v2.7.x and v2.8.0 release notes. No stage owns
the distinction between *relevant release evidence* and *current release
evidence*. The corpus A TEMPORAL aggregate is only 0.800 criteria / 0.733
score, while explicit release probes pass because their version token already
dominates lexical scoring.

## Failures

### T6 Context Wrong-Version Selection

* **Observed example:** the current Open5GS release probe retrieves several
  release-note documents and does not prioritize v2.8.0.
* **Root cause:** retrieval score is relevance-only. Source document version is
  not available as a validity signal.
* **Affected layer:** retrieval → context compilation.
* **Fix:** derive a conservative VersionIdentity from explicit metadata/title,
  resolve the latest comparable source version, and boost exact current scope
  while retaining superseded history for historical queries.

### T5 Query Temporal Intent Missed

* **Observed example:** “current/latest”, “old version”, “from 26.2 to 26.3”,
  and validity forms all collapse to the broad `temporal` label.
* **Root cause:** 0.4 routing has intent, but no current, historical,
  explicit-version, evolution, compare, validity, introduced, or removed
  behavior.
* **Affected layer:** query router → retrieval/context selection.
* **Fix:** add bounded degradable TemporalQuery parsing and expose it in
  diagnostics.

### T1 Version Metadata Missing

* **Observed example:** release-note content can be selected even though the
  compiled Knowledge Unit does not preserve that it belongs to v2.7.x or v2.8.0.
* **Root cause:** semantic SourceDocuments and Knowledge Units had no
  version/release/effective/published/source-authority projection.
* **Affected layer:** source metadata → knowledge compiler → semantic memory.
* **Fix:** reuse existing source metadata and title text; keep absent values
  UNKNOWN/null and never use file mtime.

### T4 Superseded Fact Still Active / T7 Conflict Not Exposed

* **Observed example:** only a narrow “Version X supports …” fixture was
  superseded in 0.4. Source-version facts and explicit supersession relations
  were absent; conflict status was not surfaced as temporal selection evidence.
* **Root cause:** supersession was content-pattern-only and did not create an
  auditable relation or source-version explanation.
* **Affected layer:** temporal knowledge compilation.
* **Fix:** group only same normalized scope, require comparable identities,
  mark supersession/conflict, and persist an evidence-backed relation. Unknown
  ordering remains queryable without a current claim.

## Explicit non-goals

No full graph database, ontology, theorem prover, autonomous memory agent, new
parser IR, embedding framework, or distributed worker is introduced. Temporal
selection remains a deterministic SQLite-backed compilation and retrieval
enhancement.
