# Shutu-Knowledge 0.5 Temporal Validation

Run date: 2026-09-19 (Africa/Cairo). Artifact:
`benchmarks/real_world_internalization/results/latest.json`. Baseline:
`benchmarks/real_world_internalization/results/baseline_0.4.json`.

## Method

The fixed harness was expanded from 120 to 160 real-corpus queries while
retaining the original 120 for a like-for-like regression. The corpus adds four
Open5GS release notes (v2.6.6, v2.7.1, v2.7.2, v2.7.7) and the 0.3.1 release
notes/report to Shutu-Knowledge corpus C. Embeddings remain disabled so the
result measures deterministic temporal selection, not a model upgrade.

The 40 new temporal queries cover CURRENT (7), EXPLICIT_VERSION (10),
HISTORICAL (5), EVOLUTION (3), COMPARE (3), INTRODUCED_IN (3), REMOVED_IN (3),
VALIDITY (3), and CONFLICT (3). Together with the 13 original TEMPORAL cases,
the run contains 53 temporal/version queries.

## Temporal knowledge audit

Across the three compiled corpora:

* 91 versioned Knowledge Units were audited: 91/91 had exact IR/chunk
  provenance.
* Corpus A contributed 41 and corpus C contributed 50.
* The Open5GS/3GPP corpus contained no explicit same-scope supersession pairs.
  The compiler correctly left all 0 real-corpus automatic supersession relations
  rather than guessing from differing content or file dates.
* A dedicated exhaustive fixture checked 30 comparable version pairs
  (`TestTemporalSupersessionAuditExhaustivelyChecksThirtyPairs`): all 30 had a
  provenance-backed `supersedes` relation, an older `superseded` unit, a newer
  active unit, and comparable VersionIdentity ordering.
* Same-version contradiction fixtures remained `conflicted`, queryable, and
  excluded from the active fact lane.

The benchmark runs the update and delete paths; rollback/restart evidence comes
from the named Go lifecycle tests. Version scope is serialized with the existing
metadata envelope, so an old 0.4 KB opens normally with UNKNOWN/null temporal
fields and does not require a forced recompile.
