# 0.6 Candidate Gaps

These observations are intentionally recorded, not implemented in 0.5.

| Candidate | Evidence / reason to defer | Entry condition |
|---|---|---|
| Domain-aware temporal extraction | Title and explicit metadata solve the audited corpus, but parser-native effective/revision dates would improve CJK and PDF coverage. | A real corpus exposes versions not present in metadata/title and causes measured current-selection errors. |
| Explicit supersession extraction | Automatic supersession is conservative and the real corpus has no false auto-supersession, but release notes often state changes in external links. | LLM/lexical extraction can add relations with auditable provenance and a measured false-supersession rate below the release gate. |
| Time-interval knowledge lifecycle | 0.5 stores optional valid/published/effective values; scheduling and interval joins remain out of scope. | At least 40 real validity queries require interval intersection beyond current/history behavior. |
| Graph traversal for multi-version impact | Evolution paths are one-hop and explicit. | A measured gap requires traversal over three or more evidence-backed versions. |
| Memory consolidation | Repeated versioned facts may eventually need summarized history without losing boundaries. | Storage/query cost or recall audit demonstrates a real win over immutable per-generation units. |
| Code intelligence | Current code knowledge relies on the 0.4 compiler. | A real code temporal migration corpus shows retrieval/support failure not fixed by version-aware selection. |
