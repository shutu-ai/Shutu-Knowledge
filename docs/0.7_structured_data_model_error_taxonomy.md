# 0.7 structured data model error taxonomy

| Code | Failure | Detection signal | Severity | Required response |
|---|---|---|---|---|
| SD1 | Schema detection failure | A schema-like workbook falls back to ordinary Excel; confidence and fixture evidence identify the miss. | P1 | Improve conservative signal thresholds; never force non-dictionary Excel into schema mode. |
| SD2 | Logical table detection failure | One sheet contains multiple regions but compiler emits fewer/more regions. | P1 | Preserve blank/repeated-header/heading boundaries and record region anchors. |
| SD3 | Header mapping failure | Field/type/meaning columns are transposed or dropped. | P1 | Audit multi-row/merged headers and keep per-column source anchors. |
| SD4 | Field scope loss | Same-name fields from different tables are merged or queried without scope. | P0 | Treat base/document/table/scope as identity; regression must prove zero false merges. |
| SD5 | Enum corruption | `value -> meaning` pairs are split, reordered, or lost. | P1 | Preserve ordered mapping with source anchor; uncertain text stays unresolved. |
| SD6 | Same-name wrong merge | `id/status/name/type/value/date` are merged only by name. | P0 | Deduplicate only by exact source identity/fingerprint plus explicit confidence. |
| SD7 | Semantic field miss | Business-language query does not recall relevant fields. | P1 | Improve scoped field representation and concepts; do not equivalence-collapse similar fields. |
| SD8 | Table expansion failure | A table query omits fields or attaches fields from another table. | P0 | Enforce table/field foreign identity and audit field ownership. |
| SD9 | Cross-workbook set failure | Multi-concept intersection omits a qualifying table or returns unrelated evidence. | P1 | Use concept -> field -> table set operations with bounded diagnostics. |
| SD10 | Join hallucination | Output states a required FK/JOIN without explicit evidence. | P0 | Emit only `JOIN_CANDIDATE` with confidence, reason, and evidence; unsupported claims are errors. |
| SD11 | Requirement decomposition failure | A business requirement misses a required concept or reports false certainty. | P1 | Resolver must expose concepts, candidates, unknowns, and evidence. |
| SD12 | Wrong concept mapping | A generic lexicon assigns an unsupported domain abstraction. | P1 | Concepts must carry derived-from evidence; uncertain mappings have lower confidence. |
| SD13 | Context compilation failure | Schema context exceeds budget or omits selected candidates/evidence. | P1 | Enforce bounded, deterministic context compilation and report omitted-count diagnostics. |
| SD14 | Provenance error | Entity points to absent document/node/range. | P0 | Validate source references and fail closed rather than publishing invalid schema knowledge. |

Severity policy:

- P0 blocks candidate publication and requires a deterministic regression.
- P1 requires targeted repair before final ACCEPTABLE/STRONG classification.
- Ranking/UI polish is P2 and must not mask P0/P1 failures.
