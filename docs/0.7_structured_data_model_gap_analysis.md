# 0.7 structured data model gap analysis

Source evidence: the fixed 50-workbook corpus, v0.6.3 real-scale runtime run, and the
unchanged 150-question QA harness. Private workbook, sheet, table, and field values are
not reproduced here.

## Baseline signals

| Category | BM25 | Hybrid | Hybrid + reranker | Primary failure signal |
|---|---:|---:|---:|---|
| Exact (50) | 50/50 | 46/50 | 46/50 | Exact text survives, so ingestion is not the main defect. |
| Semantic reverse (30) | 7/30 | 7/30 | 7/30 | Business intent has no field-entity representation. |
| Cross-workbook (30) | 0/30 | 0/30 | 0/30 | Chunk retrieval cannot express field-set/set operations. |
| Analysis (20) | 2/20 | 3/20 | 3/20 | Requirements are not decomposed into concepts/tables/fields. |
| Join/data-model (20) | 0/20 evidence | 0/20 evidence | 0/20 evidence | Keys and joins are ordinary text, not typed candidates. |

Runtime is no longer the v0.6.2 blocker: 154,475/154,475 chunks embedded, runtime
search completed without timeout, and reranker remained stable. The failure boundary is
representation and structured reasoning.

## Failure -> layer -> mechanism

| Failure | Example type | Root cause | Layer | Proposed 0.7 mechanism |
|---|---|---|---|---|
| A Chinese business query cannot find `imsi`, `msisdn`, or similar concrete fields | Semantic reverse | A chunk contains a spreadsheet row, but “user identifier” is not represented as a scoped Field with concepts/aliases. | Representation | Compile field-definition rows into Field entities and build a bounded field semantic representation. |
| Exact table names work, but table purpose and field inventory are not retrievable as one object | Exact/table | Logical tables are projected as sheet/table/row chunks; there is no LogicalTable aggregate. | Representation / Knowledge compiler | Detect schema-like regions and publish LogicalTable + ordered Field references with source provenance. |
| Same English/Chinese header labels are indistinguishable across tables | Scope collision | Chunk text has contextual rows, but field identity is not represented as scope + table + field. | Representation | Field IDs and retrieval filters include base/document/table/scope; never merge by name alone. |
| Multi-row and merged headers are read as unrelated chunks | Header mapping | Parser has cell metadata but does not normalize category + field header rows into a schema header. | Knowledge compiler | Detect up to two header rows, propagate merged/category context, and store header provenance. |
| Enum labels remain isolated row text | Enum query | `value -> meaning` mappings are not parsed into a typed Enum. | Representation / compiler | Extract bounded enum mappings from enum columns/cells and attach them to Field. |
| “Across workbooks” only increases result diversity | Cross-workbook | There is no entity-to-table index, so intersection of concept field sets is impossible. | Retrieval / reasoning | Resolve concepts to candidate Field sets, map to table IDs, then intersect/group by workbook. |
| Business requirement yields unrelated chunks | Analysis | No requirement decomposition or DataRequirement resolver. | Query understanding / resolver | Classify DATA_REQUIREMENT, resolve concepts in order, group candidate tables/fields, and expose unknowns. |
| Candidate joins are guessed from text co-occurrence | Join/data-model | Key candidates and FK confidence are not modeled. | Structured reasoning | Derive cautious KeyCandidates from names/types/concepts; always emit candidate, never mandatory FK. |
| Structured evidence citations are weaker than workbook/sheet/range provenance | Provenance | Derived schema entities do not exist, so chunk anchors are the only provenance. | Provenance | Every Table/Field/Enum/Concept/KeyCandidate stores source anchors and a bounded evidence closure. |
| More TopK increases noise without solving multi-concept queries | Context assembly | Context is chunk-ranked rather than schema-assembled. | Context compiler | Compile bounded concept -> fields/tables/evidence context with explicit budget, unknowns, and diagnostics. |

## PH0 layer conclusion

- Representation is the dominant root cause for semantic reverse, cross-workbook,
  and requirement failures.
- Scope is missing from entity identity and must be part of every schema object.
- Retrieval cannot be repaired only with another model or larger TopK.
- The compiler must be evidence-grounded and fail closed: uncertain purpose, enum
  mappings, joins, and business meanings must remain candidate/inferred/unknown.
