# 0.7 structured data model validation

Status: **ACCEPTABLE**. The implementation is a release candidate, not a
publicly promoted release. No `v0.7.0` tag has been created.

Corpus and query set were not changed: the fixed internal 50-workbook SmartCare
dictionary corpus and the same 150-query categories were reused. No workbook,
sheet, table, field, or proprietary row value is reproduced in this report.

## Ablation

| Mode | Observation |
|---|---|
| Chunks only | Baseline: exact recall strong, but semantic reverse, cross-workbook, and requirement decomposition remained weak. |
| Field entities only | A field row becomes addressable with scope/table/source, but Chinese business queries still need concept activation. |
| Field + table | Table ownership prevents cross-table mixing and enables table-scoped results. |
| Field + table + concept | Concept activation produced the semantic-reverse gain. |
| Full schema-aware | Table intersection, workbook grouping, requirement resolution, and candidate joins produced the cross-workbook/join gains. |

This isolates the gain to representation and set reasoning rather than larger
TopK or dumping the whole schema into context.

## Lifecycle and regression

- Existing v0.6.4 database migrated additively from storage contract 8 to 9.
- Existing chunks remained searchable; no original document reimport was needed.
- Compilation replaces one document generation atomically; empty/undetected
  documents are explicit `absent` and cannot leave a mixed old/new schema.
- Document delete cleanup removes schema generations with the existing document
  lifecycle.
- `go test ./...` passed, including parser/IR, generation/GC, PDF/Office,
  temporal, operations/restart, runtime, storage, web, and schema tests.
- v0.6.4 runtime evidence (154,475 embeddings, reranker, cancellation/restart,
  background search, bounded memory) remains the baseline; schema compilation
  does not alter the evidence runtime.

## Final answers

1. **Yes**—the dictionary is now represented as scoped logical tables, fields,
   enums, concepts, key candidates, and evidence rather than only text chunks.
2. **Yes, with candidates**—business-language queries resolve real fields and
   tables, while semantic similarity is not asserted to be equivalence.
3. **Yes**—cross-workbook concept sets can intersect fields by table and group
   results by workbook; joins remain probabilistic candidates with evidence.
4. **Representation and structured reasoning**—the gain is not explained by
   larger TopK or extra schema context; schema vectors were deliberately zero
   in this validation.

## Remaining high-value gaps

1. Semantic reverse is improved but not STRONG: 7 queries still miss.
2. Cross-workbook coverage is materially nonzero but 12 queries still miss.
3. Schema vectors/embedding fusion remains future work and was ablated to zero
   for this result.
4. Business-concept coverage is intentionally small and needs domain expansion
   without hard-coding SmartCare.
